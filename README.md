# TypeR2C: Requirement-Type-Aware Requirements-to-Code Traceability

Implementation of a type-aware LLM framework for requirements-to-code
traceability, with baseline methods and evaluation scripts. The study uses
four public datasets (eTour, eANCI, iTrust, LibEST) and one anonymized
industrial dataset.

This is a code release with frozen evaluation metadata. Raw datasets,
precomputed experiment results, predictions, and LLM caches are not included.

## Mapping to the paper

Identifiers in the code and in the frozen metadata predate the terminology
used in the paper. They map as follows:

| Code / frozen metadata | Paper |
| --- | --- |
| `Proposed Framework`, `Proposed-PairClassifier` | TypeR2C |
| `BAN` | Bidirectional semantic alignment |
| `SRCV` | Self-reflective verification |
| `DCAR` | Dynamic context-adaptive retrieval |
| `evidence_anchored_v3_dependency_context` | TypeR2C (full configuration) |
| `Ablation: w/o Type Understanding` | w/o Type Understanding |
| `Ablation: w/o Dependency Context` | w/o Dependency Context |
| `Ablation: w/o Bi-Alignment` | w/o Bi-Alignment |
| `Ablation: w/o Verification` | w/o Verification |
| `Sentence-BERT` | S-BERT |
| `Generic RAG-LLM` | RAG-LLM |
| `TFIDF` | TF-IDF |

The threshold reported for TypeR2C in the paper corresponds to the
`evidence_anchored_v3_dependency_context` row of
`audit/pair_classification_validation/threshold_calibration.csv`. Earlier
`evidence_anchored` variants are retained in that file as part of the
calibration record; `evidence_anchored_v2` is the configuration without
dependency context and therefore reports the same values as the
`w/o Dependency Context` ablation.

## Structure

```text
configs/          Configuration, frozen splits, and candidate-pair manifests
src/              Framework, baselines, evaluation code
scripts/          Entry points for running experiments
audit/            Frozen thresholds and their calibration record
requirements.txt  Python dependencies
```

## Setup

Use Python 3.10 or later. Run commands from the repository root, preferably
in a virtual environment.

```bash
pip install -r requirements.txt
```

## Preparing data

Obtain the corresponding normalized benchmark separately and place it under
`Data/`, or set `project.data_root` in `configs/datasets.yaml` to its local
location. The candidate-pair manifests do not include requirement texts or
source code.

Each configured dataset directory must contain:

- `requirements.csv`, with columns `Req_ID`, `Type`, `NFR_Type`, `Notes`,
  `Requirement_File`, and `Is_No_Code`;
- `trace_links.csv`, with columns `Req_ID` and `Code_File` (if `Label` is
  present, positive links must have the value `positive`);
- requirement text files under `req/` or `requirements/`, referenced by
  `Requirement_File` relative to the dataset directory;
- source files under `code/` or `source_code/`.

Requirement and code identifiers must match the frozen manifests. The
industrial requirement texts and source code are confidential and are not
distributed. Its anonymized pair manifest is retained as evaluation metadata,
but the industrial dataset is not enabled in the default loader configuration.
Running its experiments requires authorized access to the corresponding data.

## Running experiments

After preparing the data, validate it and generate the baseline scores:

```bash
python scripts/validate_data.py --dataset eTour
python scripts/run_rq1.py
python scripts/run_ir_baselines.py --dataset eTour
python scripts/run_neural_baselines.py --dataset eTour
```

Neural baselines require downloading the configured model weights. For a
pair-classification example using the frozen candidate pairs and thresholds:

```bash
python scripts/run_pair_classification.py --dataset eTour --method TFIDF --split all
python scripts/evaluate_pair_classification.py --dataset eTour --method TFIDF
```

The evaluator reports held-out metrics separately in `heldout_*.csv`.

IR and neural pair-classification runs read the scores generated by their
baseline scripts; these files are created locally under `results/`.

LLM methods require the provider API key in the environment (for example,
`OPENAI_API_KEY`). Do not put API keys in configuration files. To estimate
API cost without making live calls:

```bash
python scripts/run_pair_classification.py --dataset eTour --method "Direct Prompting" --split heldout
```

Add `--live-api` to run the experiment with paid API calls. Use `--help` to inspect
the available framework variants, ablations, and model options. The
end-to-end retrieval workflow is provided separately by
`scripts/run_proposed_framework.py` and `scripts/run_full_corpus_retrieval.py`;
its candidate-selection protocol differs from the pair-classification track.

## Frozen evaluation metadata

- `configs/validation_split.json`: requirement-level validation split.
- `configs/pair_classification_manifests/`: candidate pairs, gold labels,
  validation/held-out assignments, and excluded-requirement records.
- `configs/pair_classification_protocol.yaml`: pair-sampling and evaluation protocol.
- `audit/pair_classification_validation/threshold_calibration.csv`: frozen
  per-method thresholds and the associated validation calibration record.
- `configs/final_framework_config.yaml`: frozen retrieval-framework settings,
  separate from the pair-classification thresholds.

Keep these files unchanged when reproducing the released protocol. Report
held-out metrics for generalization; full-manifest metrics include validation
requirements.
